# 학사일정 기능 작업 계획서

Last updated: 2026-05-23

## 현재 상태
- 주요 파일: `calendar.html`, `calendar.js`, `calendar.css`
- 기준 샘플 파일
  - `c:\Users\panth\Downloads\5학년_1반_연간시간표.pdf`
  - PDF 1.6 형식이며 내부 스트림이 압축되어 있어 단순 문자열 검색만으로는 시간표 텍스트가 바로 노출되지 않는다.
  - 1차 구현에서는 이 파일을 대표 PDF 샘플로 삼아 파일 첨부 기반 AI 분석 또는 PDF 파서 기반 텍스트 추출 결과를 비교한다.
- 현재 구현된 뼈대
  - 연간 시수 통계표 렌더링
  - 기간 탭 기반 시간표 렌더링
  - 날짜/교시별 과목 선택 및 로컬 저장
  - 기본 주간 시간표 일괄 적용
  - 목표 시수 편제 설정
  - PDF/이미지 파일을 Gemini로 분석해 `schedule`과 `allocation`을 반영하는 흐름
- 보완이 필요한 지점
  - HWPX 파일 입력 및 분석 경로가 아직 명확하지 않다.
  - 사용자 화면과 코드의 일부 한글 문자열이 깨져 있다.
  - 분석 결과 검수, 오류 처리, 변경 이력, 교시 교환 기능이 부족하다.

## 1단계: 문서와 화면 기준 정리
- PRD 기준으로 1차/2차 기능 범위를 확정한다.
- 표준 과목명 목록, 과목명 별칭, 창체/학교자율시간 분류 규칙을 정리한다.
- 학년도, 2학기 시작일, 운영 기간을 하드코딩하지 않고 설정값으로 관리할 기준을 만든다.
- 깨진 한글 문자열을 복구해 사용자 화면 문구와 코드 상수를 정리한다.

## 2단계: 파일 업로드와 분석 파이프라인
- 업로드 허용 형식을 `application/pdf`, `.hwpx`, 필요 시 이미지로 정리한다.
- PDF 분석
  - 우선 `5학년_1반_연간시간표.pdf`를 대표 샘플로 삼아 날짜/교시/과목/시수표 추출 정확도를 검증한다.
  - 현재 Gemini 분석 흐름을 유지하되 프롬프트와 JSON 스키마를 고정한다.
  - 분석 결과가 JSON fenced block, 일반 JSON, 배열형 schedule 중 어떤 형태로 와도 정규화한다.
  - PDF 파서 도입 시 텍스트 추출형 PDF와 이미지형 PDF를 구분하고, 이미지형은 파일 첨부 기반 AI 분석 또는 OCR 경로로 보낸다.
- HWPX 분석
  - HWPX가 ZIP/XML 기반 문서임을 전제로 클라이언트 또는 서버 함수에서 텍스트를 추출하는 방식을 검토한다.
  - 브라우저에서 처리하기 어렵다면 Vercel/Netlify Function으로 업로드 파일을 보내 텍스트 추출 후 AI 분석을 수행한다.
- 분석 결과 검수 화면
  - 반영 전 추출된 시수 기준과 시간표 건수를 요약해 보여준다.
  - 사용자가 "반영"을 눌렀을 때 기존 데이터 병합 또는 덮어쓰기를 선택하게 한다.

## 3단계: 시간표 표시 UX 개선
- 기간 탭을 월별 또는 월/기간 혼합 탐색으로 개선한다.
- 날짜 헤더에 월일, 요일, 공휴일/토요일 여부를 명확히 표시한다.
- 1~10교시 표시를 유지하되 학교 설정에 따라 기본 교시 수를 조정할 수 있게 한다.
- 모바일에서 주간 표가 읽히도록 가로 스크롤 또는 카드형 축약 뷰를 점검한다.

## 4단계: 연간 시수 통계 고도화
- 통계 계산 로직을 별도 순수 함수로 분리한다.
- 1학기/2학기 기준일을 설정값에서 읽도록 변경한다.
- 과목별 목표 대비 부족/초과 상태를 색상과 숫자로 구분한다.
- 시간표 원본 데이터와 통계표 합계가 항상 일치하는지 테스트 데이터를 만든다.

## 5단계: 2차 편집 기능
- 과목 수정
  - 기존 과목 선택 모달을 정리하고 삭제, 사용자 정의 과목, 최근 사용 과목을 제공한다.
  - 수정 후 `academic_change_log`에 변경 전/후 값을 기록한다.
- 1:1 교시 교환
  - "교환 모드"를 추가한다.
  - 첫 번째 칸 선택 후 두 번째 칸을 선택하면 두 값의 교환 내용을 확인 모달로 보여준다.
  - 확인 시 두 키의 값을 swap하고 통계를 재계산한다.
- 변경 이력
  - 최근 변경 20개를 로컬 저장소에 보관한다.
  - 변경 이력에서 날짜, 교시, 변경 유형, 변경 전/후 과목을 확인할 수 있게 한다.

## 6단계: 저장과 복구
- 로컬 저장 키를 명확히 관리한다.
  - `academic_schedule`
  - `academic_target_hours`
  - `academic_metadata`
  - `academic_change_log`
- 로그인 사용자의 서버 저장이 필요하면 Supabase 테이블 설계를 추가한다.
- 원본 분석 결과와 사용자가 수정한 결과를 구분해 저장할 수 있게 한다.

## 7단계: 검증
- 샘플 파일 검증
  - PDF 3종, HWPX 3종
  - 표준 시간표, 변형 과목명, 시수표 위치가 다른 파일을 포함한다.
- 기능 검증
  - 파일 분석 후 시간표 표시
  - 시수 편제 반영
  - 과목 수정 후 통계 재계산
  - 교시 교환 후 두 칸과 통계 반영
  - 새로고침 후 데이터 유지
- 기술 검증
  - `npm.cmd run build`
  - 주요 화면 브라우저 확인
  - 콘솔 오류 확인

3. PDF 분석 결과 검수 화면 추가
4. HWPX 텍스트 추출 방식 결정 및 구현
